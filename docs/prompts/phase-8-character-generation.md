
```json
{
  "characters": [
    {
      "name": "Character name",
      "prompt": "Detailed portrait prompt of at least 50 words",
      "isAdult": true
    }
  ]
}
```

The generated set may contain one or two characters.

`isAdult` is a transient structured-output assertion only and is not persisted.



constraint did not by itself enforce the hard maximum of two characters because

### 4. Atomic replacement guard

The character-set replacement must guard against a stale execution writing
after pipeline state has changed.

The ownership/acquisition check and the complete character replacement must
occur within the same SQLite transaction.

Inside that transaction verify:

- `projectId`;
- `userId`;
- `runningStep = CHARACTERS`;
- `stepState = RUNNING`;
- exact `stepStartedAt` acquisition timestamp.

Only after that guard succeeds may the transaction:

- delete the previous generated character set;
- insert the fully validated replacement at positions `0` and `1` as
  applicable.

If the guard or any insert fails:

- rollback the entire transaction;
- do not leave partial or replaced data behind.

Do not perform the state check outside the transaction followed by separate
writes.

`isAdult` is not persisted.

It exists only to strengthen the structured model-output contract.

## Character persistence

Generated characters are persisted with deterministic positions:

```text
first generated character  → position 0
second generated character → position 1
```

Character generation uses complete-set replacement.

It never appends generated characters to an existing set.

The logical persistence operation is:

```text
begin SQLite transaction
→ verify exact acquired pipeline execution
→ delete previous generated character set
→ insert entire validated replacement
→ commit
```

The transaction guard verifies:

```text
projectId
userId
runningStep = CHARACTERS
stepState = RUNNING
stepStartedAt = exact acquisition timestamp
```

Therefore an old Gemini request cannot write its result after its acquired
pipeline execution has been recovered, failed, replaced, or otherwise changed.

If the guard fails, no character replacement occurs.

If any insert fails, the transaction rolls back and the previous character set
is preserved.

A partially persisted generated set is therefore not an accepted state.

## Durable retry checkpoint

CHARACTERS follows the same cost-conscious checkpoint principle introduced for
STYLE, but persisted character rows are not blindly treated as successful
generation.

A persisted character set may skip another Gemini call only during a qualified
explicit retry.

Checkpoint qualification uses the pre-acquisition pipeline snapshot.

The retry must correspond to a failed CHARACTERS execution with the expected
completed predecessor.

The persisted set must also be complete and valid.

Among the validated conditions are:

```text
1–2 persisted characters
positions contiguous from 0
valid persisted name
valid persisted prompt
expected portrait-generation initial state
```

An arbitrary existing character row is therefore not enough to bypass Gemini.

The implementation deliberately does not use:

```text
characters.length > 0
```

as a completion rule.

## Lost final pipeline completion

A particularly important paid-call failure case is:

```text
Gemini generation succeeds
→ character set persists successfully
→ PipelineService final completeStep transition is lost
```

The request must not falsely report successful pipeline completion.

The operation remains recoverable through the existing pipeline mechanism.

After the acquired run becomes stale:

```text
RUNNING CHARACTERS
→ explicit stale recovery
→ FAILED CHARACTERS
```

A subsequent explicit retry receives the valid failed-step retry context.

The CHARACTERS executor can then validate the already-persisted complete
character set as a durable checkpoint.

The retry becomes:

```text
explicit CHARACTERS retry
→ validate persisted checkpoint
→ zero additional Gemini calls
→ return from executor
→ retry pipeline completeStep
```

This prevents paying for another Gemini generation solely because the final
pipeline state transition was lost.

If Gemini succeeds but the character-set persistence itself fails, no durable
checkpoint exists.

That execution fails and a later explicit retry may require another Gemini
call.

No automatic retry is performed.
